# LogicHive フローチャート図

本ドキュメントでは、LogicHive の主要な内部ロジックを詳細に定義します。高レベルな概要だけでなく、各判定ノードの具体的な閾値やエラーハンドリング、非同期処理のライフサイクルを含みます。

---

## 1. 品質ゲート (Quality Gate) 判定詳細フロー

アセット保存時にトリガーされる検証パイプラインの全容です。
単なる「成功/失敗」ではなく、重み付けによる最終スコアリングの仕組みを図解します。

```mermaid
flowchart TD
    Start("(1) アセット保存要求") --> HashCheck{"コードハッシュ重複チェック"}
    HashCheck -- "既存あり" --> RejectDup["重複エラーで拒否"]
    HashCheck -- "新規" --> Structural{"同期バリデーション<br/>(Structural / Python Static)"}
    
    Structural -- "構文エラー(Score=0)" --> RejectSyntax["構文エラーで拒否"]
    Structural -- "パス" --> SavePending["SQLiteにStatus: 'pending'で保存"]
    
    SavePending --> BgStart["(2) 非同期検証開始<br/>(Background Task)"]
    
    subgraph ParallelEval ["並列評価 (Evaluation Manager)"]
        direction TB
        E1["Deterministic (AST解析)<br/>・テストなし: 0点<br/>・密度不足: -20点/個<br/>・呼び出しなし: 50%減"]
        E2["Security Static (脆弱性スキャン)<br/>・正規表現パターンマッチ<br/>・秘密情報の混入検出"]
        E3["Dependency Vouch (依存関係検証)<br/>・OSV API (脆弱性DB) 照会<br/>・未知の依存を検出"]
        E4["Runtime (サンドボックス実行)<br/>・仮想環境(uv)の払い出し<br/>・テストコード実行"]
    end
    
    BgStart --> ParallelEval
    
    ParallelEval --> VetoCheck{"致命的な拒否条件 (Veto) の確認"}
    
    VetoCheck -- "Security Score < 60" --> Fail["Status: failed<br/>(セキュリティ拒否)"]
    VetoCheck -- "Dependency Score < 70" --> Fail
    VetoCheck -- "Runtime Status: FAILURE" --> Fail
    VetoCheck -- "Runtime Status: TIMEOUT" --> Error["Status: error<br/>(システムエラー)"]
    
    VetoCheck -- "致命的欠陥なし" --> WeightedScore["加重平均スコアの算出"]
    
    subgraph Weights ["スコア配分"]
        W1["Deterministic (30%)"]
        W2["Runtime (30%)"]
        W3["Static/Security (20%)"]
        W4["AI Opinion (15%)"]
        W5["Metrics (5%)"]
    end
    
    WeightedScore --> AIReview{"AI Forensic Audit (AI Gate)"}
    
    AIReview -- "Score < 30 (Quality Theater)" --> Fail
    AIReview -- "Score < 70" --> ClampScore["AIスコアを上限値として採用"]
    AIReview -- "パス" --> CalcFinal["最終スコア確定"]
    
    ClampScore --> CalcFinal
    
    CalcFinal --> Threshold{"最終スコア >= 70?"}
    Threshold -- "No" --> Fail
    Threshold -- "Yes" --> Enrich["メタデータ補完 (Gemini/Ollama)"]
    
    Enrich --> Embedding["ベクトル生成 & ChromaDB同期"]
    Embedding --> Verified("(3) Status: verified")
```

## 2. インフラ：環境プール (Pool Manager) ライフサイクル

サンドボックス実行時の遅延（Cold Start）を最小化する、事前加温（Pre-warming）の仕組みです。

```mermaid
flowchart TD
    Init("(1) システム起動") --> Cleanup["旧プールディレクトリの消去<br/>(rename-then-delete)"]
    Cleanup --> DetectGPU{"NVIDIA GPUの検出"}
    DetectGPU --> WorkStart["(2) バックグラウンドワーカー起動"]
    
    subgraph Worker ["プール維持ループ (10秒毎)"]
        CheckPool{"プールサイズ < POOL_MAX_SIZE?"}
        CheckPool -- "No" --> Sleep["スリープ"]
        CheckPool -- "Yes" --> PrepareEnv["新規仮想環境の構築"]
        
        subgraph StepPrepare ["構築ステップ"]
            uvVenv["uv venv --system-site-packages"]
            uvPip["uv pip install (hardlink最適化)"]
        end
        PrepareEnv --> StepPrepare
        StepPrepare --> AddQueue["Queueへ追加 (READY)"]
    end
    
    WorkStart --> Worker
    
    ReqEnv["(3) 実行リクエスト"] --> Acquire{"プールから取得試行 (5秒待機)"}
    Acquire -- "成功" --> RunTest["サンドボックス内実行"]
    Acquire -- "タイムアウト" --> ColdStart["その場で新規作成 (Cold Start)"]
    
    RunTest --> Release["環境の破棄 (シングルユース)"]
    ColdStart --> RunTest
    Release --> Worker
```

## 3. ハイブリッド検索 (Hybrid Search) 実行フロー

自然言語による曖昧な問い合わせから、高精度なアセットを抽出する多段階プロセスです。

```mermaid
flowchart TD
    Query("(1) 自然言語クエリ入力") --> Expand{"Query Expansion (AI)"}
    Expand --> Emb["クエリのベクトル化"]
    
    subgraph Retrieval ["1次抽出 (Top N*3)"]
        VecSearch["ChromaDB: セマンティック検索"]
        SqlSearch["SQLite: メタデータ/タグ検索"]
    end
    
    Emb --> Retrieval
    
    Retrieval --> Merge["結果の統合 & 重複排除"]
    
    Merge --> Rerank{"AI Re-ranking (LLM分析)"}
    
    Rerank --> ScoreCheck{"トップの類似度 < 0.45 且つ<br/>'create/make'等の意図あり?"}
    
    ScoreCheck -- "Yes (結果が弱い)" --> DraftGen["Auto-Draft生成 (AI)"]
    ScoreCheck -- "No" --> FinalResult("(2) 最終結果の返却")
    
    DraftGen --> FinalResult
```
