# ADR-0016: OS 統合およびクリーンなアンインストール戦略の採用

- **Date**: 2026-06-06
- **Status**: Proposed
- **Deciders**: ayato-labs (ユーザー), Gemini CLI

## Context
LogicHive は AI エージェント（Cursor, Cline 等）が依存するインフラストラクチャとして機能するため、高い可用性（自動起動・自己修復）が求められる。
これまでは ADR-0013 に基づき、タスクスケジューラ設定は「手動」としていたが、以下の理由からアプリケーションによる自動制御へ方針を転換する：
1. **可用性の向上**: 1時間ごとの死活監視（Watchdog）により、ハブの不意の停止から自動復旧させる。
2. **信頼性の担保**: インストーラーを使用しないポータブル形式だからこそ、OS 設定やデータを完全に消去する「アンインストール機能」を提供することで、ユーザーに安心感を与える。
3. **ユーザー体験 (UX)**: 手動設定の障壁を取り除き、設定 GUI からワンクリックで OS との統合・解除を行えるようにする。

## Decision
`LogicHive-Settings.exe` に以下の機能を実装する。

### 1. タスクスケジューラへの登録 (Persistence)
- **Windows タスクスケジューラ** を利用し、以下の2つのトリガーを設定可能にする。
    - **ログオン時**: ユーザーが PC にサインインした際に自動で Hub を起動。
    - **1時間ごと**: Hub が停止している場合のみ再起動する死活監視タスク。
- 登録前にユーザーの明示的な確認（YES/NO）を GUI で取得する。
- 登録には管理者権限が必要となるため、権限昇格のフローを考慮する。

### 2. クリーンなアンインストール (Clean Uninstall)
「立つ鳥跡を濁さず」を実現するため、以下のステップを順次実行する機能を GUI に設ける。
1. **プロセス終了**: 実行中の Hub および Settings プロセスを安全に停止。
2. **OS 設定削除**: 登録済みのタスクスケジューラエントリを削除。
3. **データ削除 (オプション)**: ユーザーの確認後、`~/.logichive` ディレクトリを完全に削除。
4. **自己消去 (Kamikaze Script)**: 最後に、2つの実行ファイル（Engine/Settings）を削除する。Windows のファイルロックを回避するため、一時バッチファイルを生成し、本体終了直後に遅延削除を実行させる。

## Consequences
### Positive
- ハブの可用性が大幅に向上し、AI エージェントからの接続失敗が低減される。
- OS を汚さない設計により、プロフェッショナルなツールとしての信頼が向上する。
- ユーザーは手動でのタスク操作や隠しフォルダの削除から解放される。

### Negative / Risks
- **UAC 昇格の必要性**: タスク操作には管理者権限が必要となり、実装が複雑化する。
- **パス依存性**: ポータブル形式のため、EXE の移動によりタスクが破損するリスクがある。登録時に「パスの固定」を推奨する案内が必要。
- **誤操作リスク**: データの全削除は不可逆であるため、警告ダイアログの設計を慎重に行う必要がある。
